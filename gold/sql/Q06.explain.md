# Q06 in SQL, clause by clause

Question: between October 1 and December 31, 2009 (UTC), which five issues across all
projects had the most logged hours while remaining unresolved, ranked with their projects?

Both files read only schema `model` as the reader login: `model.logged_time` (one row per
time entry: `issue_key`, signed `seconds`, `logged_at` in UTC, `history_id`) and
`model.issue` (`project_key`, `resolution_name`).

## `Q06.answer.sql`

The `totals` step:

- `FROM model.logged_time AS t INNER JOIN model.issue AS i ON i.issue_key = t.issue_key`:
  each entry joins its one issue, so no entry is repeated and each amount is summed once
  (checklist item 5).
- `i.project_key IN (...) AND (i.resolution_name IS NULL OR i.resolution_name = '')`:
  **step 1**, the seven project population with a current resolution that is missing,
  null or exactly `''` (checklist item 6). Current values only: the reading note does not
  ask that the issue stayed unresolved through the period.
- `t.seconds > 0` and `t.logged_at >= TIMESTAMPTZ '2009-10-01 00:00:00+00' AND
  t.logged_at < TIMESTAMPTZ '2010-01-01 00:00:00+00'`: **step 2**, positive entries
  (checklist item 7) logged in the half open UTC interval, with an explicit offset
  (checklist item 2). `logged_at` is the history's `created` in UTC (spec 0006 AC-14).
- `GROUP BY i.issue_key, i.project_key`: **step 3**, an issue with no retained entry has
  no row to group, so it is excluded. `project_key` rides along, one value per issue.
- `sum(t.seconds) AS seconds`: **step 4**, the retained amounts per issue, in seconds (the
  reading note divides by 3600 for display only).

The `ranked` step and the final `SELECT`:

- `rank() OVER (ORDER BY seconds DESC)` with `WHERE place <= 5`: **step 5**, highest
  first with the tie inclusive cut. `rank` gives tied totals the same place and skips
  after them, so `place <= 5` keeps every issue whose total is at least the fifth total:
  the top five and every issue tied with the fifth, or every issue when fewer than five
  qualify. The 5 is the question's own number (checklist item 10).
- `ORDER BY seconds DESC, issue_key`: the rank order the scorer reads. Tied issues may
  come in any order; `issue_key` only makes it repeatable.

The Q06 adapter turns each row, in order, into `issue:<issue_key>` with its `seconds`. It
reads no `project_key`: a ranking item carries an ID and a value only, so the project is
returned for the reader and is not scored. The adapter cuts nothing; the query did.

## `Q06.sources.1.sql`

The known answer has one source step, with kinds `issue` and `time_entry`: for every
returned issue, each contributing entry.

- The `entries` step holds the conditions of **step 1** and **step 2** row by row.
- The `ranked` step sums them per issue (**step 3**, **step 4**) and ranks with the same
  `rank()` rule (**step 5**).
- `SELECT DISTINCT e.issue_key AS issue, e.history_id AS time_entry ... WHERE r.place <=
  5`: one row per contributing entry of a returned issue, a column per kind, the entry as
  its bare history ID. The `issue` column repeats per entry and is read as a set; every
  returned issue has an entry, so no cell is empty.

## The difference from the Cypher pair

The same reading, with a different way to make the cut. Cypher has no `rank()`, so it
sorts the totals, takes the fifth total (or the lowest when fewer than five) and keeps
every total at or above it. That keeps exactly the rows `rank() <= 5` keeps: a total
above the fifth ranks before it, a total equal to it shares its rank of at most 5, and a
total below it ranks 6 or later.
