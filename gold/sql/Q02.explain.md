# Q02 in SQL, clause by clause

Question: in CWD, how many issues are already marked Fixed in a version that has not yet
been released?

Both files read only schema `model` as the reader login: `model.issue` (one row per issue,
its project in `project_key`, its resolution in `resolution_name`), `model.fixed_in` (one
row per issue and fix version pair) and `model.fix_version` (one row per version, its
released flag in `is_released`, never null).

## `Q02.answer.sql`

- `FROM model.issue AS i WHERE i.project_key = 'CWD'`: **step 1**, the CWD population.
  The reading note sets no date bounds, so there are none.
- `i.resolution_name = 'Fixed'`: **step 2**, marked Fixed. An exact match: a null or empty
  resolution never equals `'Fixed'`, so both drop out (checklist item 6).
- `EXISTS (SELECT 1 FROM model.fixed_in AS f INNER JOIN model.fix_version AS v ... WHERE
  f.issue_key = i.issue_key AND v.is_released = false)`: **step 3**, at least one fix
  version not yet released. `EXISTS` asks a yes or no question per issue, so an issue with
  two unreleased versions is still one row; nothing is joined into the outer query to
  repeat it. An issue with no fix version at all has no `fixed_in` row and drops out.
- `count(DISTINCT i.issue_key) AS issues`: **step 4**, each retained issue counted once.
  `count` gives 0, not NULL, when nothing qualifies (checklist item 3). `DISTINCT` is not
  needed after `EXISTS` (no join can repeat an issue here) and is kept as a guard
  (checklist item 5).

The Q02 adapter reads the one row's `issues` value as the number. It adds nothing.

## `Q02.sources.1.sql`

The known answer has one source step, of kind `issue`: the qualifying issues.

- `SELECT DISTINCT i.issue_key AS issue`: one column named after the kind, one issue key
  per row. With no qualifying issue the result is empty and the step is kept as
  `issue: []` (checklist item 11).
- The `WHERE` holds the same conditions as the answer file: **step 1** (CWD), **step 2**
  (Fixed), **step 3** (an unreleased fix version). These are the issues **step 4** counts.

## The difference from the Cypher pair

None in meaning. SQL reads the project from the `project_key` column and the fix versions
through the `fixed_in` table; the graph reads them as `IN_PROJECT` and `FIXED_IN`
relationships. Both come from the same `model_int` tables.
