# Q07 in SQL, clause by clause

Question: which issues have the largest difference between their original estimates and
actual logged time, and who logged time against them?

Both files read only schema `model` as the reader login: `model.logged_time` (one row per
time entry: author `person_key`, `issue_key`, signed `seconds`, `history_id`) and
`model.issue` (`project_key`, `time_original_estimate_s` in seconds, null when missing).

## `Q07.answer.sql`

The `totals` step:

- `FROM model.logged_time AS t INNER JOIN model.issue AS i ON i.issue_key = t.issue_key`:
  each entry joins its one issue, so each amount is summed once (checklist item 5).
- `i.project_key IN (...) AND i.time_original_estimate_s > 0`: **step 1**, the seven
  project population with a current estimate above 0. A null estimate fails `> 0` and
  drops out (checklist item 6).
- `t.seconds > 0`: **step 2**, positive entries only (checklist item 7). The flagged bot
  set is empty for this corpus (spec 0006 AC-17), so no bot clause is written. An issue
  with no positive entry has no row to group, so it is excluded.
- `GROUP BY i.issue_key, i.time_original_estimate_s` with `sum(t.seconds)`: **step 3**, the
  retained amounts per issue. The estimate is in the `GROUP BY` because it is one value
  per issue, read once, never summed.
- `abs(i.time_original_estimate_s - sum(t.seconds)) AS difference`: **step 4**, the
  absolute difference in seconds, so an issue far over and an issue far under its
  estimate rank alike.

The `ranked` step and the final `SELECT`:

- `rank() OVER (ORDER BY difference DESC)` with `WHERE place <= 10`: **step 5**, highest
  first with the tie inclusive cut. Tied differences share a place and the next place
  skips, so `place <= 10` keeps every issue whose difference is at least the tenth: the
  top 10 and every issue tied with the tenth, or all when fewer than 10 qualify. The 10 is
  the question's own number (checklist item 10).
- `ORDER BY difference DESC, issue_key`: the rank order the scorer reads; tied issues in a
  repeatable order.

The Q07 adapter turns each row, in order, into `issue:<issue_key>` with its `difference`.
It cuts nothing; the query did.

## `Q07.sources.1.sql`

The known answer has one source step, with kinds `issue`, `person` and `time_entry`: for
every returned issue, each contributing entry and who logged it.

- The `entries` step holds the conditions of **step 1** and **step 2** row by row.
- The `ranked` step sums them per issue (**step 3**), takes the absolute difference
  (**step 4**) and ranks with the same `rank()` rule (**step 5**).
- `SELECT DISTINCT e.issue_key AS issue, e.person_key AS person, e.history_id AS
  time_entry ... WHERE r.place <= 10`: one row per contributing entry of a returned issue.
  The `person` column is **step 6**, the distinct authors of the retained entries: an
  author appears once per entry and is read as a set, so each person counts once. The
  entry is its bare history ID. No cell is empty, since every row is an entry.

## The difference from the Cypher pair

The same reading, with a different way to make the cut: SQL uses `rank() <= 10`, Cypher
keeps every difference at or above the tenth (or the lowest when fewer than 10). Both
keep the same rows: a difference above the tenth ranks before it, one equal to it shares
its rank of at most 10, and one below it ranks 11 or later.
