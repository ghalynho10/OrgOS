# Q12 in SQL, clause by clause

Question: in CLOUD and CLOV, which parent issues have sub-tasks assigned to multiple
people, and who are those people?

Both files read `model.issue` (`issue_key`, `project_key`, `parent_key` and
`assignee_key`, each NULL when missing). A child names its parent in `parent_key`.

## The rulings this pair follows

Your rulings of 2026-11-02, recorded in the body of main repo commit `1d793bd`: ruling
4, Q12 reading B, the step lists `issue`, `parent` and `person`; ruling 5, a parent hop
adds the kind `parent` holding the direct child keys. The scope is CLOUD and CLOV.

## `Q12.answer.sql`

- `FROM model.issue AS c INNER JOIN model.issue AS p ON p.issue_key = c.parent_key`:
  **step 2**, each direct sub-task with its parent, by the child's `parent_key`. One join
  is one hop, so a grandchild never reaches its grandparent.
- `p.project_key IN ('CLOUD', 'CLOV')`: **step 1**, parents in the two projects.
- `c.project_key IN ('CLOUD', 'CLOV') AND coalesce(c.assignee_key, '') <> ''`: **step 3**,
  sub-tasks in the two projects with an assignee that is not NULL and not `""`
  (checklist item 6). The flagged bot set is empty for this corpus (spec 0006 AC-17), so
  no bot clause is written.
- `GROUP BY q.parent_key` with `count(DISTINCT q.assignee_key)`: **step 4**, the distinct
  assignee keys per parent (checklist item 5).
- `HAVING ... >= 2`: **step 5**, the parents with at least two, each once.

The Q12 adapter turns each row into `issue:<issue_key>`. It adds and drops nothing.

## `Q12.sources.1.sql`

The known answer has one source step, with kinds `issue`, `parent` and `person`.

- `contributing` and `qualifying`: **step 1** to **step 5**, as in the answer file.
- The first `SELECT`: each qualifying parent's own issue record, in `issue`. Its
  `parent` and `person` cells are NULL, which under AC-12 as amended on 2026-11-12 is no
  ID.
- The second `SELECT`: every contributing sub-task of a qualifying parent, its issue
  record in `issue`, its parent hop in `parent` (the child key, ruling 5), and its
  assignee in `person`. So every qualifying assignee is in the step, as the note asks.

## Checklist notes

No date bound applies (item 2). The one count is `count(DISTINCT ...)`, not a sum
(item 3). No group with a zero is listed (item 4). No path is built, so item 9 does not
apply. The only number is the two assignees the question asks for; no ID is written
(item 10).
