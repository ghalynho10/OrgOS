# Q02 in Cypher, clause by clause

Question: in CWD, how many issues are already marked Fixed in a version that has not yet
been released?

Both files read the read only `neo4j` database: `Issue` nodes (resolution in
`resolutionName`), the `IN_PROJECT` relationship to a `Project` (key `projectKey`) and the
`FIXED_IN` relationship to a `FixVersion` (released flag in `isReleased`, always set).

## `Q02.answer.cypher`

- `MATCH (i:Issue)-[:IN_PROJECT]->(p:Project) WHERE p.projectKey = 'CWD'`: **step 1**, the
  CWD population. Every issue has exactly one `IN_PROJECT` relationship, so this matches
  each CWD issue once. No date bounds apply.
- `i.resolutionName = 'Fixed'`: **step 2**, marked Fixed. An exact match: a missing
  property (null) or an empty string never equals `'Fixed'` (checklist item 6).
- `EXISTS { (i)-[:FIXED_IN]->(v:FixVersion) WHERE v.isReleased = false }`: **step 3**, at
  least one fix version not yet released. `EXISTS` is a yes or no test per issue, so an
  issue with two unreleased versions is not matched twice.
- `RETURN count(DISTINCT i) AS issues`: **step 4**, each retained issue counted once.
  `count` gives 0 when nothing matches (checklist item 3); `DISTINCT` is a guard, since no
  pattern here repeats an issue (checklist item 5).

The Q02 adapter reads the one row's `issues` value as the number. It adds nothing.

## `Q02.sources.1.cypher`

The known answer has one source step, of kind `issue`: the qualifying issues.

- `RETURN DISTINCT i.issueKey AS issue`: one column named after the kind, one issue key per
  row; an empty result is kept as `issue: []` (checklist item 11).
- The `MATCH` and `WHERE` hold the same conditions as the answer file: **step 1** (CWD),
  **step 2** (Fixed), **step 3** (an unreleased fix version). These are the issues
  **step 4** counts.

## The difference from the SQL pair

None in meaning. The graph follows `IN_PROJECT` and `FIXED_IN` relationships where SQL
reads the `project_key` column and joins `fixed_in` to `fix_version`. Both come from the
same `model_int` tables.
