# Q11 in Cypher, clause by clause

Question: which people are connected through shared issue assignments, reporting,
creation, and time logging, and which projects connect them?

Both files read the read only `neo4j` database: `Issue` nodes and their one
`IN_PROJECT` relationship to a `Project`, the `ASSIGNED_TO`, `REPORTED_BY` and
`CREATED_BY` relationships from an `Issue` to a `Person` (absent when the key is
missing), and `LOGGED_TIME` relationships from the author `Person` to an `Issue` (signed
`seconds`, `historyId`).

## The ruling this pair follows

Your ruling of 2026-11-02, recorded in the body of main repo commit `1d793bd`, ruling 6:
Q11 reading A, the step lists `issue` and `time_entry`.

## `Q11.answer.cypher`

- `MATCH (i:Issue)-[:IN_PROJECT]->(pr:Project) WHERE pr.projectKey IN [...]`: **step 1**,
  the issues of the seven projects.
- `CALL (i) { ... }`, its first part: **step 2**, the assignee, reporter and creator of
  the issue. A missing key has no relationship, so it never matches (checklist item 6).
  The flagged bot set is empty for this corpus (spec 0006 AC-17), so no bot clause is
  written.
- Its second part: **step 3**, the authors of positive time entries on the issue,
  `t.seconds > 0` (checklist item 7).
- `collect(DISTINCT x.personKey) AS people` with `WHERE size(people) >= 2`: **step 4**,
  an issue connects people when at least two distinct people hold a role on it. A person
  with several roles on an issue counts once. Every person on such an issue has someone
  else to be connected to, and its project supports that connection.
- `CALL (pr, people) { UNWIND people ... UNION RETURN 'project' ... }` then `RETURN
  DISTINCT kind, id`: **step 5**, every person on a shared issue, as `person`, and every
  project of a shared issue, as `project`, each once, in one set (checklist item 5).

The Q11 adapter turns each row into `<kind>:<id>`. It adds and drops nothing.

## `Q11.sources.1.cypher`

The known answer has one source step, with kinds `issue` and `time_entry`.

- The same match, roles and `size(people) >= 2` as the answer file: **step 1** to
  **step 4**.
- `OPTIONAL MATCH (:Person)-[t:LOGGED_TIME]->(i) WHERE t.seconds > 0`: every positive
  time entry on a shared issue, each of which establishes its author's logging role
  (**step 3**). The `WHERE` sits inside the `OPTIONAL MATCH`, so a shared issue with no
  positive entry keeps one row with a null `time_entry`, which under AC-12 as amended on
  2026-11-12 is no ID; the issue still counts in the `issue` column.

## Checklist notes

No date bound applies (item 2). Nothing is summed (item 3). No group with a zero is
listed (item 4). No path is built, so item 9 does not apply. The only number is the two
people a connection needs; no ID is written (item 10).

## The difference from the SQL pair

None in meaning. SQL reads the three current roles as key columns of `model.issue` and
time entries as rows of `model.logged_time`; a missing key is no relationship here and
NULL there.
