# Q05 in Cypher, clause by clause

Question: which people have logged hours on issues assigned to someone else, and how many
hours have they logged on those issues?

Both files read the read only `neo4j` database: `LOGGED_TIME` relationships from a
`Person` (the entry's author) to an `Issue`, each holding its signed `seconds` and its
changelog `historyId`; the issue's one `IN_PROJECT` relationship to a `Project`; and its
`ASSIGNED_TO` relationship to a `Person`, present only when the issue has an assignee.

## `Q05.answer.cypher`

- `MATCH (author:Person)-[t:LOGGED_TIME]->(i:Issue)-[:IN_PROJECT]->(p:Project) WHERE
  p.projectKey IN [...]`: **step 1**, the entries on issues in the seven project
  population. Each `LOGGED_TIME` relationship is one entry, matched once.
- `t.seconds > 0`: **step 3**, positive entries only (checklist item 7, spec 0006 AC-15).
- `MATCH (i)-[:ASSIGNED_TO]->(assignee:Person)`: **step 2**, an issue with no assignee has
  no `ASSIGNED_TO` relationship, so its entries do not match and drop out (checklist item
  6). An issue has at most one assignee, so this second `MATCH` repeats no entry
  (checklist item 5). The flagged bot set is empty for this corpus (spec 0006 AC-17), so
  no bot clause is written, for assignees or authors.
- `WHERE assignee.personKey <> author.personKey`: **step 3**, the entry's author is not
  the issue's current assignee.
- `RETURN author.personKey AS person_key, sum(t.seconds) AS seconds`: **step 4**, the
  retained amounts summed per author, in seconds. Only authors with a retained entry form
  a row, so no author gets a 0.

The Q05 adapter turns each row into `person:<person_key>` with its `seconds`. It adds no
person, fills no zero and sums nothing.

## `Q05.sources.1.cypher`

The known answer has one source step, with kinds `issue` and `time_entry`.

- `RETURN DISTINCT i.issueKey AS issue, t.historyId AS time_entry`: one row per
  contributing entry, a column per kind; the `issue` column repeats per entry and is read
  as a set. Every listed issue has an entry, so neither column holds a null.
- The `MATCH` and `WHERE` clauses are the answer file's: **step 1**, **step 2**,
  **step 3**. These are the entries **step 4** sums.

## The difference from the SQL pair

None in meaning. The graph follows `ASSIGNED_TO` where SQL reads `assignee_key`, and the
entry's author is the start of `LOGGED_TIME` where SQL reads `person_key`. Both come from
the same `model_int` tables.
