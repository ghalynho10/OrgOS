# Q07 in Cypher, clause by clause

Question: which issues have the largest difference between their original estimates and
actual logged time, and who logged time against them?

Both files read the read only `neo4j` database: `LOGGED_TIME` relationships from a
`Person` (the author) to an `Issue` (signed `seconds`, `historyId`), the issue's
`timeOriginalEstimateS` (absent when missing) and its one `IN_PROJECT` relationship.

## `Q07.answer.cypher`

- `MATCH (:Person)-[t:LOGGED_TIME]->(i:Issue)-[:IN_PROJECT]->(p:Project)`: one row per
  entry; each issue has one project, so no entry is repeated (checklist item 5).
- `p.projectKey IN [...] AND i.timeOriginalEstimateS > 0`: **step 1**, the seven project
  population with an estimate above 0. An absent estimate compares as null and drops out
  (checklist item 6).
- `t.seconds > 0`: **step 2**, positive entries only (checklist item 7); an issue with no
  positive entry never reaches the next row. The flagged bot set is empty for this corpus
  (spec 0006 AC-17), so no bot clause is written.
- `WITH i, sum(t.seconds) AS logged`: **step 3**, the retained amounts per issue.
- `WITH i, abs(i.timeOriginalEstimateS - logged) AS difference`: **step 4**, the absolute
  difference in seconds, from the issue's own single estimate.
- `ORDER BY difference DESC`, `collect(...) AS ranked`, `coalesce(ranked[9].difference,
  ranked[-1].difference) AS cutoff`, then `UNWIND ranked AS r ... WHERE r.difference >=
  cutoff`: **step 5**, highest first with the tie inclusive cut. Index 9 is the tenth
  item (a list starts at 0); when fewer than 10 qualify it is out of range, gives null,
  and the last and lowest difference is used, so every issue is kept. The 9 and the 10 it
  stands for are the question's own number (checklist item 10).
- `RETURN r.issue_key, r.difference ORDER BY difference DESC, issue_key`: the rank order
  the scorer reads; tied issues in a repeatable order.

The Q07 adapter turns each row, in order, into `issue:<issue_key>` with its `difference`.
It cuts nothing.

## `Q07.sources.1.cypher`

The known answer has one source step, with kinds `issue`, `person` and `time_entry`.

- The same `MATCH` and `WHERE` (**step 1**, **step 2**), then beside the sum (**step 3**)
  `collect({person: author.personKey, entry: t.historyId}) AS entries`, so each issue
  carries exactly the entries its total was summed from, each with its author.
- The same difference, sort, cutoff and cut (**step 4**, **step 5**), then `UNWIND
  r.entries`: one row per contributing entry of a returned issue, as `issue`, `person`
  and `time_entry` (the bare history ID). The `person` column is **step 6**, the distinct
  authors of the retained entries, read as a set so each counts once. No cell is empty.

## The difference from the SQL pair

The same reading, with a different way to make the cut: SQL uses `rank() <= 10`, Cypher
keeps every difference at or above the tenth. Both keep the same rows: a difference above
the tenth ranks before it, one equal to it shares its rank of at most 10, and one below
it ranks 11 or later.
